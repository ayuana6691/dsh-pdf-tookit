# 验证与排错

## 三类证据

1. **结构**：输出可以重开；页数、页尺寸、旋转角度符合预期；关键链接、表单和书签按任务需要检查。保存程序会低分辨率渲染每页，但不验证所有 PDF 标准。
2. **内容**：精确数出替换次数；检查旧文字是否残留、新文字是否可提取；表格核对行列、表头及合并单元格；图片检查提取数量与页面渲染一致性。扫描页不应假装有文字。
3. **视觉**：渲染受影响页面并打开 PNG 查看。关注重叠、裁切、字体替代、字号变化、彩色/透明背景和旋转页。对局部编辑，用相同渲染器与 dpi 对比；预期区域外非零像素差异必须解释或修复。

像素一致只能证明该分辨率下显示一致，不能证明结构、可访问性、提取顺序、表单数据或签名一致。PyMuPDF 文字替换会重写内容流，阅读顺序、字体子集资源和字距可能变化，因此不能称为“原文件字节不变”。

## 表单

`fill` 同时验证 `/AcroForm/Fields` 的 `/V`、页面 Widget 的有效 `/V` 和 `/AP/N` 存在；重开渲染可发现外观异常。flatten 会绘制全部现有字段值，移除 Widget 和字段树。未知字段、签名字段、XFA 或不支持的状态会失败。

对于孤立 Widget、字段树损坏或自定义脚本表单，不盲目 `reattach_fields()`，以免重复创建字段。先检查结构并选择修复方案；本插件不自动修复损坏表单。

## 常见失败

- `ModuleNotFoundError`：用 setup 安装依赖；明确给 Harness 配置同一个 Python。
- `Output already exists`：改用新路径；不自动覆盖用户文件。
- 替换字体缺字：提供用户允许的 font_file，或保留原文并报告确切限制。不悄悄换成 Helvetica。
- 新文字更宽：选 expand 需有足够空间；shrink 明确改变字号。复杂段落重排应使用文档源文件或另行实现，不声称可无损自动处理。
- 找到文本但可编辑数不一致：可能是跨行、竖排、多个样式、连字或碎片化文本；不能只替换部分就报告成功。
- 压缩后更大：如实返回 saved_bytes；本操作不损失图片质量，不保证减小文件。
- 超时/取消：单文件最终发布之前会清理临时文件（进程强制终止时可能留临时文件）；多文件操作可能留下部分输出。先检查返回和输出再继续。

## 本插件依赖如何对应原流程

- pypdf：文档对象、页树、合并拆分、元数据、加密、表单和内容流压缩。
- pdfplumber：表格识别与结构化提取。
- PyMuPDF：常规文本和图像提取、页面渲染、字体资源读取、文字替换、裁切、装饰和区域涂销。
- Pillow：像素差分、预期区域掩码、图片方向校正。
- reportlab：文本及图片生成 PDF。
- Poppler 的 pdftoppm/pdfinfo：原工作流使用的外部渲染与检查工具，本插件通过 doctor 检测，保留为人工交叉验证选择；插件核心不依赖这些系统命令。
- Node.js：DeepSeek Harness 工具注册、技能注册、进程生命周期、JSON 协议、错误与取消传递。

这些是独立可安装的依赖，不携带 Codex 的专用工具、路径或内部 artifact 标记程序。
